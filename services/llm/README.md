# llm — скрытый RAG-сервис платформы

Перенесён из Innopolis (`llm/rag`, кейс БАРС Груп) и доработан под платформу. Наружу не публикуется:
единственный клиент — `admin`, он ходит с `ADMIN_API_TOKEN` по внутренней сети и сам подставляет `project_id`.

**Что изменилось при переносе**

- Пакет `bars_rag` → `rag_service`; справочник продукта и глоссарий агента вынесены в `config/product.yaml`
  (по умолчанию пустой; профиль демо-базы БАРС — `config/product.demo-bars.yaml`, база — `data/demo_kb`).
- **Разделы документации**: загрузки лежат в `<проект>/<раздел>/<файл>`, у документа есть `section`;
  `replace` заменяет раздел, а не всю базу; одинаковое имя файла в двух разделах — `409`.
- **Доступ по разделам на запрос**: `/ask` принимает `allowed_sections`; на время хода они превращаются в набор
  скрытых документов (контекстная переменная), который учитывают поиск, инструменты агента, кэши и ссылки.
- `DELETE /documents/{doc_id}`, `GET /documents/staged`, `GET /jobs?project_id=`.
- Ответы поддержки, сохранённые в базу (`/knowledge`), пишутся в папку **своего** проекта и раздел
  (в Innopolis они попадали в общую папку и терялись для всех проектов, кроме дефолтного).
- Пересчёт FAQ по расписанию идёт для всех проектов; состояние проекта при откате пишется атомарно.
- Токенизатор чанкера запекается в образ; без сети считает токены приближённо, а не падает.

Тесты: `.venv/bin/pytest` (269 тестов без сети и ключей).

## Описание сервиса (из Innopolis)

RAG-сервис (FastAPI). В платформе к нему подключается только `admin` по диалоговому контракту
`ask(session_id, project_id, message, images?, allowed_sections?)` → поток событий `status` / `delta` / `final`
(в Innopolis так же подключался Telegram-бот).

Бот отвечает **только по документации**: каждый факт в ответе подкреплён номером `[N]` и дословной цитатой,
а код проверяет ссылки, цитаты и числа. Если опоры нет, бот предлагает оператора: «Я пока не нашёл точного
ответа. Переключить на оператора?» и кнопку «Связаться с поддержкой».

## Быстрый старт

```bash
cp .env.example .env            # вписать OPENROUTER_API_KEY и GEMINI_API_KEY / EMBEDDING_API_KEY, SERVICE_API_TOKEN и ADMIN_API_TOKEN
docker compose -f services/llm/docker-compose.yml up -d --build   # из корня: только llm со своими Qdrant, Redis и Postgres

curl -sN localhost:8080/ask -H "Authorization: Bearer $SERVICE_API_TOKEN" -H 'Content-Type: application/json' \
     -d '{"session_id":"u1","message":"Кто согласовывает БП Командировки?"}'
```

Индексировать вручную не нужно: если опубликованной базы ещё нет, сервис при старте сам индексирует `data/kb`
(FR-ADM-02). Ход индексации виден в `GET /jobs`.

Без Docker (dev): `python -m venv .venv && .venv/bin/pip install -e .[dev]`, затем
`AUTH_DISABLED=true uvicorn rag_service.api.app:app --port 8080`. Без `QDRANT_URL` используется встроенный Qdrant
в `var/qdrant`, без `REDIS_URL` сессии хранятся в памяти процесса, без `DATABASE_URL` — sqlite в `var/rag.sqlite`.
CLI: `python -m rag_service.cli ingest data/kb | search "…" | ask "…"`.

## API

Все методы, кроме `/health`, требуют `Authorization: Bearer <token>`. Если токены не заданы, методы отвечают 503,
а не открываются. `SERVICE_API_TOKEN` — для бота, `ADMIN_API_TOKEN` — для панели (подходит и для методов бота).

| Токен | Метод | Путь | Что делает |
|-------|-------|------|------------|
| бот | POST | `/ask` | SSE: `status`, затем `delta` (проверенные абзацы по мере генерации), при необходимости `reset`, затем `final` |
| бот | POST | `/ask/sync` | тот же контракт одним JSON (скрипты, eval) |
| бот | POST | `/sessions/{id}/reset` | `/new`: сброс памяти диалога |
| бот | POST | `/feedback` | 👍/👎 к ответу по `request_id` (идёт в аналитику и FAQ-кэш) и отметка дежурного «эскалация была не нужна» |
| бот | POST | `/knowledge` | ответ дежурного становится документом базы «Ответ поддержки, <дата>» (FR-ESC-06) |
| бот | GET | `/images/{image_id}` | скриншот или схема по `image_ids` из ответа; `?crop=true` — фрагмент в рамке (FR-ING-06) |
| бот | GET | `/images/user/{name}` | скриншот, который прислал пользователь (для карточки эскалации) |
| бот | GET | `/documents`, `/documents/{doc_id}/outline` | документы активной версии базы и оглавление |
| бот или подпись | GET | `/documents/{doc_id}/view`, `/documents/{doc_id}/file` | документ как HTML с якорем на каждый раздел (`#sec-2.4.6`) и исходный файл (PDF — `#page=N`); цель ссылок `sources[].url` (FR-GEN-02). Без токена — по подписи `sig` из ссылки |
| бот | GET | `/faq/popular` | популярные вопросы для меню бота (FR-FAQ-07) |
| админ | POST | `/documents` | загрузка `.docx/.pdf/.md/.txt` (`mode=append\|replace`) и фоновая индексация |
| админ | POST | `/reindex` | переиндексация `data/kb`: новая generation, атомарная публикация (`{"wait":true}` — синхронно) |
| админ | GET | `/jobs`, `/jobs/{id}` | фоновые задачи и отчёты (FR-ING-08); хранятся в БД и переживают рестарт |
| админ | POST | `/rollback` | откат на предыдущую версию базы |
| админ | POST | `/cache/clear?level=exact\|faq\|all` | очистка точного кэша и/или авто-записей FAQ (ручные остаются) |
| админ | GET | `/analytics/summary` | запросы за день/неделю, доля успешных автоответов, эскалации, время (полное и до первого текста), темы, экономия кэша, 👍/👎 (FR-AN-02) |
| админ | GET | `/analytics/timeseries`, `/distribution`, `/doc-sections`, `/gaps`, `/dashboard` | графики по дням, темы/типы/объекты, какие разделы помогают, «чего не хватает в документации» (FR-AN-03..05) |
| админ | GET | `/analytics/requests`, `/requests/{id}` | журнал запросов; ход целиком с трейсом агента и историей оценок |
| админ | GET/PUT | `/analytics/taxonomy`, POST `/analytics/classify` | таксономия тем, кандидаты новых тем, ручной запуск классификации |
| админ | GET | `/analytics/clusters`, `/top-questions`, `/unanswered`, `/topics`, `/hot-answers`, POST `/analytics/clusters/rebuild` | кластеры вопросов, частые вопросы, пробелы в документации, отчёт по темам, горячие ответы ([Docs/questions.md](Docs/questions.md)) |
| админ | GET | `/faq/stats`, `/faq/entries…` | топ популярных вопросов и записи кэша (FR-FAQ-02) |
| админ | POST | `/faq/recompute` | пересчёт топа и пересборка ответов (FR-FAQ-01/03) |
| админ | POST/PATCH/DELETE | `/faq/entries…` | ручная запись, правка, удаление (с «не кэшировать»), история, восстановление (FR-FAQ-08) |
| админ | GET/POST/PATCH/DELETE | `/git/sources…` | Git-репозитории как источник: подключение, проверка доступа, `sync`, отключение (FR-GIT-*) |
| подпись | POST | `/webhooks/github`, `/webhooks/gitlab` | push-вебхук → инкрементальная индексация; вместо токена проверяется подпись |
| — | GET | `/health` | Qdrant, Redis, БД, активная generation, статус токенов, график смены |

Тело `/ask`: `{"session_id": "...", "project_id": null, "message": "...", "images": [{"mime": "image/png", "data_base64": "..."}], "now": null, "debug": false}`.
`now` переопределяет текущее время (показать поведение в нерабочие часы), `debug` добавляет в `final` полный журнал
вызовов инструментов с найденными фрагментами.

Событие `final`:
- `action`: `answer` | `clarify` | `offer_operator` | `escalate`;
- `text`, `formatted_text` (текст и блок «Источники: … — «цитата»»);
- `sources[]` (`citation_label`, `document_title`, `section_path`, `excerpt`, `chunk_type`, `score`, `url`): `url` — для
  Git-документа файл в коммите с якорем заголовка, для загруженного — `{PUBLIC_BASE_URL}/documents/{id}/view?sig=…#sec-N`
  или страница исходного PDF (`DOC_LINKS`, `DOC_LINK_SECRET`; подпись открывает только этот документ);
- `image_ids`, `confidence` (0..1), `confidence_level`, `reason`, `buttons`;
- для `escalate` ещё `summary`, `urgency` и `history`;
- `support`, `cache_hit`, `usage` (токены по моделям, `cost_usd`, `cost_status`), `latency_ms`, `first_token_ms`,
  `request_id`, `prompt_version`.

### Потоковая выдача

Финальный ответ приходит пользователю по абзацам, пока модель ещё пишет. Каждый абзац сначала проверяется теми же
правилами, что и весь ответ: маркеры `[N]` указывают на источники этого диалога, числа есть в источниках. Для этого
схема `final_answer` просит источники раньше текста. Непроверенный текст не показывается.

Если поздний абзац или проверка ответа целиком не проходит после того, как часть уже показана, сервис шлёт событие
`reset`: клиент убирает показанный текст и ждёт исправленный. Выключается `AGENT_STREAMING=false` — тогда ответ
приходит целиком после проверки. Если провайдер отдаёт аргументы вызова инструмента одним куском, выигрыша во
времени первого текста не будет, поведение останется корректным.

## Архитектура (Miro, раздел «2. RAG-сервис: кэш и агент»)

```
/ask ─► Guardrails: явная просьба об операторе ─► escalate (без LLM)
     └► ExactCache (Redis, ключ project_id + generation + вопрос; только самостоятельные вопросы)
     └► SemanticFaqCache (Qdrant `faq_cache`: косинус ≥ 0.84 → те же ключевые сущности → LLM-проверка эквивалентности)
     └► скриншот пользователя → VLM (текст, ошибка, экран) → авто-поиск по документации (FR-VIS-03)
     └► AgentLoop (tool calling, ≤4 поиска за ход, таймаут, бюджет токенов, защита от повторов)
          tools: search_docs · list_documents · get_section · attach_image · validate_filter · parse_bo_link
          final: final_answer · ask_clarification · offer_operator · escalate_to_operator
        ─► StreamingGuard: проверенные абзацы уходят в delta по мере генерации
        ─► Guardrails: [N] → реальный источник диалога, цитата = подстрока чанка, числа есть в источниках,
                       порог доказательств → одна попытка исправить → иначе offer_operator
        ─► Confidence ─► политика рабочего/нерабочего времени ─► final
search_docs = HybridRetriever: dense + BM25 (sparse-векторы Qdrant, IDF) → RRF → LLM-Reranker (0..10)
Ingestion: Parsers (DOCX / PDF / MD / TXT) → очистка шума → TableExtractor → ImageDescriber (VLM, кэш по sha256)
           → вырезка фрагментов с красной рамкой → Chunker → Embedder (кэш sqlite) → Publisher (generation)
Хранилища: Qdrant (чанки), Redis (сессии, точный кэш), Postgres (ходы с трейсом, оценки, задачи, ответы дежурных)
```

### В коде нет знаний о конкретных вопросах

Сервис не содержит названий документов, номеров разделов и готовых формулировок ответов. Всё, что относится к
продукту и не выводится из базы знаний, лежит в `config/product.yaml`: хосты внутренних ссылок, документированный
синтаксис фильтров, сокращения названий. Документ, на который ведёт ссылка, распознаётся по названиям из самой
базы: заголовки, разделы, подписи на скриншотах. Полнота ответа на многошаговые вопросы задаётся общими правилами
в системном промпте, а не проверками под отдельные вопросы.

### Форматы документов

`.docx` (заголовки, вложенные списки, таблицы, врезки, картинки с привязкой к месту), `.pdf`, `.md`, `.txt`.
Все четыре проходят один конвейер; тесты генерируют документ каждого формата и проверяют разбор
(`tests/test_formats.py`). В `data/kb` лежит база в Markdown с картинками; исходные `.docx`/`.pdf` можно
загрузить через `POST /documents`.

Для скриншотов, где элемент обведён рамкой, сохраняется вырезанный фрагмент (FR-ING-06): `final` сообщает
`image_meta[].has_crop`, а сам фрагмент отдаёт `GET /images/{image_id}?crop=true`.

### Уверенность и нерабочее время

`confidence` = 0.5·скор реранкера лучшего процитированного фрагмента + 0.1·разрыв top1–top2 + 0.15·число
подтверждающих фрагментов + 0.25·самооценка агента (full / partial), минус 0.1, если ответ исправлялся после
проверки. Ниже `MIN_EVIDENCE_SCORE` код не даст ответить фактами: будет `offer_operator`.

| Ситуация | Смена идёт | Нерабочее время (`SUPPORT_HOURS`, `SUPPORT_TZ`) |
|----------|------------|------------------------------------------------|
| answer · high | ответ | ответ |
| answer · medium | ответ | ответ + «Связаться с поддержкой» + когда ответит специалист |
| answer · low / частичный | ответ + кнопка | ответ + кнопка + когда начнётся смена |
| offer_operator | фраза из брифа + кнопка | то же + «обращение сохранится, специалист ответит в понедельник в 09:00» |
| escalate | «Передаю дежурному…» | обращение принято сразу (с историей), ответ — в начале смены |

### Аналитика

Каждый ход пишется в таблицу `rag_turns`: вопрос, ответ, действие, источники, уверенность, время (полное и до
первого текста), токены по моделям, стоимость, уровень маршрутизации, трейс шагов агента. Идентификатор сессии
псевдонимизирован. Стоимость берётся из ответа OpenRouter, а если провайдер её не сообщает — считается по
`MODEL_PRICES`. Оценки лежат в `rag_feedback`, результаты классификации и таксономия тем — в `rag_classes` и `rag_kv`.

## Качество (eval)

Оценка одна — модуль [`eval/rag_eval`](../../eval/README.md): golden set, правила (действие, Hit@k / MRR,
траектория, цитаты) и LLM-судья (факты, запреты, достоверность, корректность). Сервис подключается к нему
адаптером `rag_service/bench.py`, который отдаёт записи в формате [`eval/RUN_FORMAT.md`](../../eval/RUN_FORMAT.md):

```bash
make eval JUDGE_MODEL=gpt-4.1            # collect через запущенный API, затем evaluate
# то же вручную:
cd ../../eval
RAG_API_URL=http://localhost:8080 RAG_API_TOKEN=$ADMIN_API_TOKEN PYTHONPATH=../llm/rag \
  uv run python -m rag_eval collect --pipeline rag_service.bench:ask --out runs/run1.jsonl
uv run python -m rag_eval evaluate --run runs/run1.jsonl --judge-model gpt-4.1
```

`make test` — unit-тесты без сети: инструменты, guardrails, потоковая выдача, токены API, оценки и журнал,
задачи индексации и автоиндексация, разбор всех форматов, вырезка фрагментов, адаптер бенчмарка.
В CI (`.github/workflows/rag.yml`) линтер и тесты идут на каждый push; прогон eval запускается вручную.

## Модели и лимиты

Все LLM-вызовы идут через OpenRouter (`LLM_PROVIDER=openrouter`, `OPENROUTER_API_KEY`), с маршрутизацией по сложности
(`rag_service/agent/router.py`):

| Уровень | Модель | Когда |
|---------|--------|-------|
| быстрый | `deepseek/deepseek-v4.1-flash-1017` на Baseten (запасной — Wafer), рассуждения выключены | короткий самостоятельный вопрос без скриншота, не процедура / таблица / сравнение / цифры регламента, и первый поиск нашёл один уверенный фрагмент |
| тяжёлый | `deepseek/deepseek-v4.1-flash` без рассуждений, провайдеры InferenceNet → Modal (запасная `z-ai/glm-5.3-flash`) | всё остальное; скриншоты (модель принимает картинки) |

Ход начинается на быстром уровне, только если вопрос простой по тексту. Слабый или неоднозначный поиск, запрос
целого раздела, повтор после проверки цитат или ответ без инструмента переводят остаток хода на тяжёлый уровень
(назад не возвращается). Проверки цитат, кавычек и чисел в коде одинаковы на обоих уровнях. Реранкер, резюме
диалога, проверка эквивалентности FAQ и классификация — на быстром уровне. В логе хода пишутся `tier`, `route`,
`models` и реальная стоимость из OpenRouter (`usage.cost_usd`); сводка — `routing` в `/analytics/summary`.
Запись `модель@Провайдер` закрепляет провайдера (`only`, `sort=throughput`, без автозамены); при 429/502 —
одна быстрая повторная попытка и переход к следующей модели цепочки.

Внимание: значения по умолчанию в `config.py` (`EMBEDDING_MODEL=text-embedding-3-small`, `AGENT_MODEL=gpt-4.1-mini`,
`HEAVY_MODEL=Inkling`) не совпадают с `.env.example` (архитектура v2: DeepSeek-агент, `google/gemini-embedding-001`)
— без `.env` сервис встанет на них (так было в прогоне 14.11 из `experiments/2026-11-14-openrouter-baseline`).
Берите `.env.example` за основу.

Реранкер — `deepseek-v4.1-flash-1017` на закреплённых провайдерах, 12 кандидатов, потолок `RERANK_TIMEOUT_S=4`:
дольше — поиск отдаёт порядок гибридного слияния, ход не зависает на медленном провайдере.

Картинки базы описывает `google/gemini-3.8-flash` (запасная `qwen/qwen3.8-max-0902`) с промптом `VISION_PROMPT=v2`:
для схем — полный список переходов с обеими ветками каждой развилки. Кэш описаний ключуется картинкой, версией
промпта и моделью — смена модели описывает картинки заново. Если ответ ссылается на описание картинки, сама
картинка прикладывается кодом (`ATTACH_CITED_IMAGES`). Классический OCR (`rag_service/ingest/ocr.py`, PP-OCRv5 на CPU)
подключается переключателями `VISION_MODE=vlm+ocr` и `USER_IMAGE_OCR=true` (зависимость `.[ocr]`, файлы моделей
в `OCR_MODELS_DIR`); по умолчанию выключен. Страницы PDF без текстового слоя помечаются в отчёте индексации
(`page_without_text_layer`): их текст доходит до индекса только через описание картинки.

Эмбеддинги — `gemini-embedding-001` (на нашей базе не уступает bge-m3, qwen3-embedding-8b и text-embedding-3-small). Та же модель

доступна через OpenRouter как `google/gemini-embedding-001` и даёт идентичные векторы (косинус 1.0), так что
переход на неё не требует переиндексации. Смена размерности больше не стирает индекс молча: сервис откажется
пересоздавать непустую коллекцию без `ALLOW_COLLECTION_RECREATE=true`.
Описания картинок и эмбеддинги кэшируются на диске
(`data/vision_cache`, `var/embedding_cache.sqlite`), поэтому переиндексация не тратит квоту.
Что выбрано и какими замерами это доказано — в [`Docs/adr-002-architecture-v2.md`](Docs/adr-002-architecture-v2.md)
(отчёт эксперимента — `experiments/2026-11-15-architecture-v2/`); прежняя временная таблица — [`Docs/adr-001-models.md`](Docs/adr-001-models.md).
Лицензии зависимостей: только MIT, Apache-2.0, BSD и PostgreSQL License. Нет PyMuPDF и GPL; Redis взят 7.2 (BSD), Qdrant — Apache-2.0.

## Ограничения

- Telegram-бот, Jira и чат дежурных сюда не входят. Эскалация возвращает в `final` резюме, причину, срочность
  и историю; создание задачи и карточки — на стороне бота (FR-ESC-02/03).
- FAQ-кэш строится из журнала запросов: пересчёт по `POST /faq/recompute` или раз в `FAQ_RECOMPUTE_INTERVAL_S`. Сборка
  ответа для записи — обычный ход агента, поэтому стоит LLM-вызовов; в кэш попадает только ответ с высокой уверенностью.
- Журнал запросов, оценки, классификация и задачи хранятся в БД. Записи FAQ-кэша и реестр Git-источников пока лежат
  в файлах `var/faq`, `var/git`: рестарт они переживают, но в Postgres не перенесены.
- Аналитика — JSON API; веб-админки нет. Метрики дежурных (время взятия/закрытия, оценка) требуют данных Jira (FR-AN-02).
- Git-источник работает через REST API GitHub/GitLab (без git-клиента); Bitbucket и «историю документа» по коммитам (FR-GIT-06) не делали.
- Если OpenRouter недоступен или на аккаунте нет кредитов (402), сервис не падает: отвечает `offer_operator`
  с причиной `llm_unavailable` (NFR-04).
- Пороги маршрутизации (`ROUTE_FAST_*`) подобраны по смыслу и юнит-тестам; на golden set тяжёлый уровень берёт 92 % ходов (11 из 12 вопросов брифа — процедуры, таблицы, условия; `Docs/overnight-2026-11-15.md`).
- `/knowledge` запускает полную переиндексацию; она дешёвая за счёт кэшей, но не мгновенная.
- Качество на живых моделях замерено 15.11 (golden set, 3 повтора, судья inkling-2-small): см.
  [`Docs/overnight-2026-11-15.md`](Docs/overnight-2026-11-15.md).
- 4 картинки исходного документа битые: они помечены в отчёте индексации и не прикладываются к ответам.

## FAQ-кэш, Git и аналитика — коротко

**FAQ-кэш (FR-FAQ-01–08).** Раз в окно (14 дней) бот берёт самостоятельные вопросы из логов (у уточнений — переписанный
агентом вопрос), группирует похожие по смыслу (эмбеддинги + одинаковые ключевые сущности: объект, числа, операторы;
в «серой зоне» косинуса решает LLM), свежие вопросы весят больше. Для топ-20 собирается ответ обычным агентом;
в кэш идёт только ответ с высокой уверенностью и источниками. Вопрос пользователя попадает в кэш только при трёх
условиях: косинус ≥ 0.84, те же сущности («реестр мебели» ≠ «реестр техники»), LLM подтвердила эквивалентность.
Кэш привязан к версии базы: после переиндексации или отката авто-записи по неизменённым документам переносятся,
остальные пересобираются; ручные записи выключаются и помечаются «источники изменились». 3 👎 выключают запись.

**Git (FR-GIT-01–05, 07).** `POST /git/sources {"provider":"github","repo":"org/kb","branch":"main","include":["docs/**/*.md"],"token_env":"KB_GIT_TOKEN"}`,
затем `POST /git/sources/{id}/sync` или push-вебхук (секрет — в `GET /git/sources/{id}?show_secret=true`).
Первый импорт — все подходящие файлы, дальше — только изменённые по диффу коммитов (остальные чанки копируются
с векторами). Ссылка в цитате ведёт на файл в конкретном коммите с якорем заголовка. Если индексация упала,
остаётся прежняя версия базы. Токен хранится только в `.env`, в реестре — имя переменной. Отчёт синхронизации
(`last_sync.changes`) говорит, какие документы добавлены, удалены и изменены (с новыми и убранными разделами); при
заданном `DOCS_WEBHOOK_URL` сервис шлёт туда событие `docs.updated` с этим списком и текстом «Что изменилось»
(FR-ADM-05; приём на стороне бота — отдельная задача).

**Аналитика (FR-AN-02–05).** Успешный автоответ = ответ без эскалации и без 👎. Классификация запросов по темам,
типам и объектам — фоном дешёвой моделью (с запасным правилом без LLM). `/analytics/gaps` группирует вопросы,
на которые бот не ответил или получил 👎, и показывает, какие разделы он пробовал.
